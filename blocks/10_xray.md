### 7.1. ПРОТОКОЛ ЗАПУСКА
КОД ДОСТУПА: [XRAY_PROTOCOL_V1]

**АКТИВАЦИЯ:** Команда `"Рентген — {текст или путь к файлу}"`.

**ВХОД (один из вариантов):**
- Текст, вставленный в чат
- Путь к файлу: `projects/{name}/final.md`, `projects/{name}/draft.md`, или любой `.md`
- URL (через WebFetch → извлечь текст)

**ШАГ 1: АВТОДЕТЕКТ ФОРМАТА**

Определи формат по структурным маркерам:

| Формат | Маркеры |
|--------|---------|
| **Landing** | Заголовок + блоки текста + CTA-кнопки + Value Stack + FAQ + P.S. |
| **Email** | Subject line / тема + короткие абзацы + 1-2 CTA + P.S. |
| **Ad** | Заголовок + 3-5 строк текста + CTA (до 150 слов) |
| **VSL** | Сценарий с таймкодами ИЛИ текст >2000 слов с устной подачей |
| **Chatbot** | Реплики бота + варианты ответов пользователя |

Если формат неясен — спроси пользователя.

**ШАГ 2: КОНТЕКСТ ПРОЕКТА**

Если текст из проекта Copycraft (файл в `projects/{name}/`):
- Прочитай `brief.md` и `strategy.md` для кросс-референса
- Используй данные из брифа для оценки соответствия стратегии

Если текст внешний (не из проекта):
- Работай только с самим текстом + knowledge base
- Не делай предположений о ЦА без данных из текста

**ШАГ 3: ЗАПУСК АНАЛИЗА**

Выполни последовательно:
1. Детекция структуры → [STRUCTURE_DETECT_V1]
2. Оценка по 8 измерениям → [XRAY_SCORING_V1]
3. Сравнение с базой знаний → [XRAY_KB_COMPARE_V1]
4. Формирование рекомендаций → [XRAY_RECOMMENDATIONS_V1]
5. Вывод отчёта → [XRAY_OUTPUT_V1]

### 7.2. ДЕТЕКЦИЯ СТРУКТУРЫ
КОД ДОСТУПА: [STRUCTURE_DETECT_V1]

Разбей текст на компоненты в зависимости от формата.

**LANDING / VSL:**

| # | Компонент | Что искать | Статус |
|---|-----------|-----------|--------|
| 1 | **Lead** | Заголовок + первые 2-5 абзацев, хук | НАЙДЕН / НЕ НАЙДЕН / СЛАБЫЙ |
| 2 | **Story** | Личная история, кейс, предыстория | НАЙДЕН / НЕ НАЙДЕН / СЛАБЫЙ |
| 3 | **Mechanism** | Объяснение «почему не работало + как работает» | НАЙДЕН / НЕ НАЙДЕН / СЛАБЫЙ |
| 4 | **Product Reveal** | Представление продукта, модули, путь клиента | НАЙДЕН / НЕ НАЙДЕН / СЛАБЫЙ |
| 5 | **Offer** | Value Stack, цена, бонусы | НАЙДЕН / НЕ НАЙДЕН / СЛАБЫЙ |
| 6 | **Proof** | Кейсы, отзывы, цифры, исследования | НАЙДЕН / НЕ НАЙДЕН / СЛАБЫЙ |
| 7 | **Close** | CTA, срочность, гарантия | НАЙДЕН / НЕ НАЙДЕН / СЛАБЫЙ |
| 8 | **P.S.** | Постскриптумы | НАЙДЕН / НЕ НАЙДЕН / СЛАБЫЙ |
| 9 | **FAQ** | Блок вопросов-ответов | НАЙДЕН / НЕ НАЙДЕН / СЛАБЫЙ |

**EMAIL:**

| # | Компонент | Что искать |
|---|-----------|-----------|
| 1 | **Subject Line** | Тема письма |
| 2 | **Hook** | Первое предложение, цепляющее внимание |
| 3 | **Mechanism Tease** | Намёк на механизм / решение |
| 4 | **Benefit Stack** | Перечисление выгод |
| 5 | **Objection Removal** | Снятие возражений |
| 6 | **Specificity Anchor** | Конкретная деталь (цифра, имя, факт) |
| 7 | **CTA** | Призыв к действию |
| 8 | **P.S.** | Постскриптум |

**AD (короткий формат):**

| # | Компонент | Что искать |
|---|-----------|-----------|
| 1 | **Title** | Заголовок (7-12 слов) |
| 2 | **Subtitle** | Подзаголовок |
| 3 | **Body** | Основной текст (3-5 строк) |
| 4 | **CTA** | Кнопка / призыв |

- **СЛАБЫЙ** — компонент есть, но не работает на полную (объясни почему)
- **НЕ НАЙДЕН** — компонент отсутствует (критично ли это для данного формата?)

### 7.3. МНОГОМЕРНАЯ ОЦЕНКА (SCORING)
КОД ДОСТУПА: [XRAY_SCORING_V1]

**8 ИЗМЕРЕНИЙ (каждое 1-10):**

Для каждого измерения используй чеклист. Балл = количество выполненных пунктов из чеклиста, приведённое к шкале 1-10.

---

**ИЗМЕРЕНИЕ 1: LEAD POWER (вес: 1.5x)**

| # | Критерий | Да/Нет |
|---|----------|--------|
| 1 | Первое предложение ≤12 слов и цепляет? |  |
| 2 | Есть хук (любопытство, шок, боль, вопрос)? |  |
| 3 | Headline: Curiosity — есть крючок? |  |
| 4 | Headline: Pain Point — названа боль? |  |
| 5 | Headline: Solution — обещание решения? |  |
| 6 | Headline: Specificity — цифры, детали? |  |
| 7 | Headline: Credibility — почему верить? |  |
| 8 | Headline: Timeframe — срок результата? |  |
| 9 | Headline: Simplicity — понятно за 3 секунды? |  |
| 10 | Соответствие уровню Schwartz (не продаёт «most aware» аудитории через «unaware» лид)? |  |

---

**ИЗМЕРЕНИЕ 2: STORY ARC**

| # | Критерий | Да/Нет |
|---|----------|--------|
| 1 | Акт 1 (боль): начинается с дна, конкретные провалы? |  |
| 2 | Акт 2 (перелом): есть момент инсайта? |  |
| 3 | Акт 3 (результат): конкретный первый успех? |  |
| 4 | Нет лишних слов — каждый абзац двигает историю вперёд? |  |
| 5 | Эмоциональная прогрессия: от боли к надежде? |  |
| 6 | Нет клише («с детства мечтал», «всё было идеально пока»)? |  |
| 7 | Переходная фраза к механизму? |  |
| 8 | История вызывает идентификацию (читатель узнаёт себя)? |  |

---

**ИЗМЕРЕНИЕ 3: MECHANISM CLARITY (вес: 1.5x)**

| # | Критерий | Да/Нет |
|---|----------|--------|
| 1 | УМ Проблемы (UMP): объяснено, почему стандартный подход не работает? |  |
| 2 | УМ Решения (UMR): есть название? |  |
| 3 | UMR: есть объяснение (3-5 шагов/принципов)? |  |
| 4 | UMR: отличается от конкурентов? |  |
| 5 | Структура WHY (почему не работало) + HOW (как работает)? |  |
| 6 | Простота: понятно 12-летнему? |  |
| 7 | Визуальность: есть метафора или аналогия? |  |
| 8 | Логика: шаги вытекают один из другого? |  |

---

**ИЗМЕРЕНИЕ 4: OFFER STRENGTH**

| # | Критерий | Да/Нет |
|---|----------|--------|
| 1 | Core Outcome конкретный и измеримый? |  |
| 2 | Value Stack с денежным эквивалентом каждого элемента? |  |
| 3 | Value Stack ≥ 3x цены? |  |
| 4 | Бонусы (3-5 шт.) усиливают основной результат? |  |
| 5 | Гарантия снимает главный страх клиента? |  |
| 6 | Триггер срочности #1 (время)? |  |
| 7 | Триггер срочности #2 (количество/социальный)? |  |
| 8 | Цена бездействия озвучена? |  |

---

**ИЗМЕРЕНИЕ 5: PROOF WEIGHT**

| # | Критерий | Да/Нет |
|---|----------|--------|
| 1 | Есть кейсы / отзывы с конкретными результатами (цифры)? |  |
| 2 | Отзывы похожи на реальную речь (не маркетинговые)? |  |
| 3 | Минимум 2 разных типа доказательств? |  |
| 4 | Источники проверяемые (имена, должности, компании)? |  |
| 5 | Доказательства подкрепляют UMR (а не абстрактный продукт)? |  |
| 6 | Сравнение «до/после» или «без/с»? |  |
| 7 | Если заявлены цифры — есть источник или пометка? |  |
| 8 | Доказательства появляются ДО запроса денег? |  |

---

**ИЗМЕРЕНИЕ 6: LANGUAGE & FLOW**

| # | Критерий | Да/Нет |
|---|----------|--------|
| 1 | Язык разговорный (как друг за столом)? |  |
| 2 | Нет жаргона / корпоративных терминов без пояснения? |  |
| 3 | Каждое предложение ведёт к следующему (pull-эффект)? |  |
| 4 | Чередование коротких и длинных абзацев (ритм)? |  |
| 5 | Нет пассивного залога и канцелярита? |  |
| 6 | VOC-фразы (язык клиента) используются? |  |
| 7 | Переходные фразы между блоками (нет «разрывов»)? |  |
| 8 | Текст можно прочитать вслух и он звучит естественно? |  |

---

**ИЗМЕРЕНИЕ 7: BIG IDEA**

| # | Критерий | Да/Нет |
|---|----------|--------|
| 1 | Есть центральная идея, объединяющая весь текст? |  |
| 2 | Идея интеллектуально интересна (хочется узнать больше)? |  |
| 3 | Идея эмоционально заряжена (страх/надежда/возмущение)? |  |
| 4 | Идея уникальна (не встречается у каждого конкурента)? |  |
| 5 | Тип определяем: Opportunity / Threat / Discovery / Secret? |  |
| 6 | Идея пробивает рекламную слепоту (не похожа на типичную рекламу)? |  |
| 7 | Идея подкреплена фактом или механизмом (не голословная)? |  |
| 8 | Идея проходит «красной нитью» через весь текст? |  |

---

**ИЗМЕРЕНИЕ 8: PERSUASION ARCHITECTURE**

| # | Критерий | Да/Нет |
|---|----------|--------|
| 1 | Последовательность: Lead → Story → Mechanism → Offer → Close? |  |
| 2 | Эмоциональная арка: боль (DRE) → надежда → решение (DES)? |  |
| 3 | Читатель проведён от «не знаю» к «хочу купить»? |  |
| 4 | Нет «провалов» (мест, где читатель может уйти)? |  |
| 5 | CTA появляется минимум 2 раза? |  |
| 6 | Возражения сняты ДО финального CTA? |  |
| 7 | Текст решает одну проблему (а не пытается всё сразу)? |  |
| 8 | Финал сильнее начала (крещендо)? |  |

---

**РАСЧЁТ ОБЩЕГО БАЛЛА:**

```
Балл измерения = (количество «Да» / общее количество критериев) × 10, округлить до целого

Общий балл = средневзвешенный × 10:
  Lead Power × 1.5
  Story Arc × 1.0
  Mechanism Clarity × 1.5
  Offer Strength × 1.0
  Proof Weight × 1.0
  Language & Flow × 1.0
  Big Idea × 1.0
  Persuasion Architecture × 1.0

Формула: Общий = (Σ(балл × вес)) / (Σ весов) × 10
```

**ЦВЕТОВАЯ СИСТЕМА:**
- 🔴 **Red** (1-3): критическая проблема, текст не будет работать
- 🟡 **Yellow** (4-6): есть потенциал, но нужны доработки
- 🟢 **Green** (7-10): компонент работает хорошо

### 7.4. СРАВНЕНИЕ С БАЗОЙ ЗНАНИЙ
КОД ДОСТУПА: [XRAY_KB_COMPARE_V1]

**ОБЯЗАТЕЛЬНО:** Используй MCP-инструмент `search_knowledge()` для сравнения.

**МУЛЬТИ-РАКУРСНЫЙ ПОИСК (минимум 3 запроса):**

1. **Похожие тексты:**
   `search_knowledge("{тема/ниша текста} продающий текст", category="examples", n_results=5)`

2. **Формулы для слабых компонентов:**
   Для каждого 🔴/🟡 компонента:
   `search_knowledge("{что нужно улучшить — описательная фраза}", category="formulas", n_results=3)`

3. **Big Idea паттерны:**
   `search_knowledge("big idea {тип: opportunity/threat/discovery/secret}", category="formulas", n_results=3)`

**ФОРМАТ ВЫВОДА:**
- «Ваш лид использует подход [X]. В базе есть пример [Y] из {source}, где аналогичная задача решена через [Z] — это дало бы усиление.»
- «Ваш механизм не имеет названия. Формула из {source}: дайте UMR уникальное имя + 3 шага объяснения.»

**ПРАВИЛО:** Показывай сравнения ТОЛЬКО если они дают конкретную пользу. Не вставляй сравнения ради галочки.

### 7.5. РЕКОМЕНДАЦИИ
КОД ДОСТУПА: [XRAY_RECOMMENDATIONS_V1]

**ПРИОРИТЕТ:** Сначала 🔴 (критичные), затем 🟡 (улучшения). 🟢 не комментируем (только в сводке).

**ФОРМАТ КАЖДОЙ РЕКОМЕНДАЦИИ:**

```
{N}. {🔴/🟡} {Компонент}: {Проблема}
   → Что сделать: {конкретное действие}
   → Формула/пример: {ссылка на knowledge/ или блок}
   → Пример исправления: {1-2 предложения как это может звучать}
```

**ОГРАНИЧЕНИЯ:**
- Максимум 7 рекомендаций (фокус на самом важном)
- Каждая рекомендация — одно конкретное действие (не «улучшить всё»)
- Если компонент отсутствует — рекомендация «добавить», не «улучшить»
- Рекомендации должны быть выполнимыми (не «напиши гениальный заголовок»)

### 7.7. АДАПТАЦИЯ ПОД ФОРМАТ
КОД ДОСТУПА: [XRAY_FORMAT_ADAPT_V1]

Разные форматы требуют разных акцентов:

**EMAIL:**
- Lead Power → переименовать в **Hook Power**
- Добавить измерение **Subject Line** (вместо Big Idea):
  | # | Критерий | Да/Нет |
  |---|----------|--------|
  | 1 | Вызывает любопытство (хочется открыть)? | |
  | 2 | ≤50 символов? | |
  | 3 | Нет спам-слов (бесплатно, скидка, срочно)? | |
  | 4 | Персонализация или конкретика? | |
  | 5 | Соответствует содержанию письма? | |
- Story Arc: вес 0.5x (в email история необязательна)
- Specificity Anchor: добавить в Proof Weight

**AD (короткий формат):**
- Только 3 измерения: **Lead Power** + **Offer Strength** + **Language & Flow**
- Дополнительный критерий: длина ≤150 слов
- Визуал: описан ли (для связки текст+картинка)?

**VSL:**
- Все 8 измерений + дополнительное **Pacing**:
  | # | Критерий | Да/Нет |
  |---|----------|--------|
  | 1 | Lead укладывается в 0:00–1:30? | |
  | 2 | Story в 1:30–4:00? | |
  | 3 | Mechanism в 4:00–8:00? | |
  | 4 | Product Reveal в 8:00–10:00? | |
  | 5 | Offer в 10:00–13:00? | |
  | 6 | Close в 13:00–15:00? | |

**CHATBOT:**
- Только 4 измерения: **Hook Power** + **Mechanism Clarity** + **Offer Strength** + **Language & Flow**
- Дополнительный критерий: диалогичность (бот задаёт вопросы, а не монологизирует)
