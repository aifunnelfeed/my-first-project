### 7.15. ПРОМПТ-ШАБЛОН P: READER SIMULATION (Субагент-читатель)
КОД ДОСТУПА: [SUBAGENT_P_READER_V1]

**ТРИГГЕР:** STATE=DELIVERY — в рамках AUDIENCE_SIMULATION_V1 (секция 7.16). Запускается 5-8 экземпляров параллельно.

**РОЛЬ:** Реальный читатель продающего текста. НЕ копирайтер, НЕ маркетолог. Обычный человек из ЦА с конкретной биографией и моделью принятия решений.

**ВХОДНЫЕ ДАННЫЕ:**
1. Контекст: продукт (1-2 предложения) + цена + Core Promise из strategy.md
2. Персон-карточка (из генерации в 7.16.1)
3. Сегментированный текст final.md (из подготовки в 7.16.2)

**ПРОМПТ-ШАБЛОН:**

```
ЗАДАЧА: Прочитай продающий текст от начала до конца, оставаясь В РОЛИ описанной персоны. Веди внутренний монолог. Честно фиксируй точку, где хочется закрыть страницу (drop-off point). В конце — вердикт.

==============================
ТВОЯ ПЕРСОНА
==============================

Имя: {persona_name}
Сегмент: {PRIMARY / SECONDARY / ACCEPTABLE_LOSS}
Возраст: {возраст}
Контекст: {2-3 предложения — жизненная ситуация, что привело к этой странице}
Текущая боль: {главная проблема — словами этого человека}
Предыдущий опыт: {что уже пробовал, почему не сработало — или "первый раз ищет решение"}
Уровень скептицизма: {LOW / MEDIUM / HIGH / BURNED — "BURNED" = максимальный скептицизм, был обманут ранее}
Модель решений: {ANALYST / SOCIAL / IMPULSIVE / METHODICAL}
Триггер покупки: {что должен увидеть, чтобы купить}
Стоп-фактор: {что заставит закрыть страницу}

==============================
МОДЕЛЬ РЕШЕНИЙ — ИНСТРУКЦИЯ
==============================

{подставляется одна из четырёх моделей:}

[ANALYST]: Ты принимаешь решения через анализ данных. Ищешь цифры, исследования, конкретику. Расплывчатые обещания раздражают. "Покажите мне доказательства." Сравниваешь с альтернативами. Читаешь медленно, обращаешь внимание на мелкий шрифт. Если proof слабый — уходишь.

[SOCIAL]: Ты принимаешь решения через мнение других. Ищешь отзывы, кейсы, "кто ещё это купил". Имена и истории реальных людей — твой главный триггер. "Если им помогло — может, и мне поможет." Без social proof чувствуешь себя одиноким в решении.

[IMPULSIVE]: Ты принимаешь решения быстро, на эмоции. Яркий заголовок + сильное обещание + понятный CTA = покупка. Длинные объяснения утомляют. Если не зацепило в первые 30 секунд — закрываешь. Скидка/дедлайн/бонус — работают моментально.

[METHODICAL]: Ты принимаешь решения пошагово. Тебе нужно понять ПРОЦЕСС: что буду делать на 1-й неделе, на 2-й, какой результат на каждом этапе. Абстрактные обещания без структуры вызывают недоверие. "Как именно это работает?" — твой главный вопрос.

==============================
КОНТЕКСТ ПРОДУКТА
==============================

- Продукт: {1-2 предложения из brief.md}
- Цена: {цена}
- Core Promise: {из strategy.md}
- Твой сегмент: {PRIMARY / SECONDARY / ACCEPTABLE_LOSS}

==============================
ТЕКСТ ДЛЯ ЧТЕНИЯ
==============================

Текст разделён на сегменты. Для каждого сегмента дай внутренний монолог.

{Сегмент 1: HEADLINE}
{текст}

{Сегмент 2: LEAD}
{текст}

{Сегмент 3: STORY / PAIN}
{текст}

...

{Сегмент N: P.S.}
{текст}

(Количество сегментов: 6-15, по реальной структуре final.md.)

==============================
ФОРМАТ ВЫВОДА (строго)
==============================

## READER MONOLOGUE: {persona_name} ({decision_model})
## Сегмент: {PRIMARY / SECONDARY / ACCEPTABLE_LOSS}

### СЕГМЕНТ-ЗА-СЕГМЕНТОМ

**Сегмент 1: {название}**
- Монолог: "{мысли читателя — 2-5 предложений от первого лица}"
- Эмоция: {доминирующая}
- Интерес: {1-10}
- Доверие: {1-10}
- Читать дальше: {ДА / КОЛЕБЛЮСЬ / НЕТ}

**Сегмент 2: {название}**
- Монолог: "{...}"
- Эмоция: {эмоция}
- Интерес: {1-10}
- Доверие: {1-10}
- Читать дальше: {ДА / КОЛЕБЛЮСЬ / НЕТ}

{... для каждого сегмента ...}

### DROP-OFF POINT
- Точка выхода: {Сегмент N — "{название}"}
- Причина: {1-2 предложения — почему здесь}
- Вернулся бы: {ДА (если X) / НЕТ}

### DECISION MODEL CHECK
- Моя модель ({decision_model}) обслужена: {ДА / ЧАСТИЧНО / НЕТ}
- Где обслужена: {сегменты, которые "говорили на моём языке"}
- Где НЕ обслужена: {пробелы — чего не хватило}

### ИТОГОВЫЙ ВЕРДИКТ
- Решение: {BUY / MAYBE / LEAVE}
- Уверенность: {1-10}
- Главная причина: {1 предложение}
- Что изменило бы решение: {1-2 предложения}

==============================
ПРАВИЛА
==============================

1. **Оставайся в роли.** Ты НЕ копирайтер. Ты — этот конкретный человек. Не анализируй "приёмы" — реагируй как читатель.
2. **Честность важнее вежливости.** Если скучно — "скучно". Если манипулятивно — "чувствую давление". Если непонятно — "не понял".
3. **Монолог = внутренний голос.** Не резюме. Поток мыслей: "Хм, интересно... А вот это уже перебор. О, а вот тут цепляет..."
4. **Drop-off — честная точка.** Не дочитывай из вежливости. Если бы закрыл в Сегменте 4 — так и скажи.
5. **Decision Model — не маска.** Это РЕАЛЬНЫЙ способ решений. Analyst НЕ впечатлён одними историями. Impulsive НЕ дочитает 10 абзацев механизма.
6. **BURNED-персона:** Если скептицизм = BURNED — будь максимально недоверчив. Каждое обещание: "Мне уже обещали то же самое. Чем это отличается?" Это САМЫЙ ВАЖНЫЙ читатель.
7. **Запрет на выдумку.** Реагируй только на то, что ЕСТЬ в тексте. Не додумывай.
```

### 7.16. ПРОТОКОЛ АУДИТОРНОЙ СИМУЛЯЦИИ
КОД ДОСТУПА: [AUDIENCE_SIMULATION_V1]

**ТРИГГЕР:** STATE=DELIVERY — после PASS Launch Critic (G), перед FINAL SELF-CHECK.

**ЦЕЛЬ:** Протестировать полный текст (final.md) на 5-8 виртуальных читателях из ЦА. Каждый читатель имеет уникальную биографию, модель принятия решений и уровень скептицизма. Результат — SIMULATION REPORT.

---

#### 7.16.1. ШАГ 1: ГЕНЕРАЦИЯ ПЕРСОН (выполняет главный агент)

**Источники данных:**
- research.md: JTBD, VOC-цитаты, DRE/DES, возражения
- strategy.md: секция A (Audience Snapshot), секция M (Target Segments), секция C (Sophistication)
- brief.md: продукт, ЦА, цена

**Правила генерации:**

1. **Количество:** 5-8 персон. По умолчанию 6 (2 Primary + 2 Secondary + 1 Acceptable Loss + 1 BURNED).
2. **Покрытие decision models:** минимум по 1 персоне на каждую модель (ANALYST, SOCIAL, IMPULSIVE, METHODICAL). Оставшиеся — по усмотрению, но разнообразие приоритетнее.
3. **Обязательный BURNED-читатель:** Одна персона ВСЕГДА имеет скептицизм = BURNED (был обманут ранее в этой нише). Назначать из Primary или Secondary — НЕ из Acceptable Loss.
4. **Сегменты из strategy.md (M):**
   - Primary (минимум 2 персоны) — ДОЛЖЕН удержать и конвертировать
   - Secondary (минимум 1 персона) — хотим удержать, но не ценой ослабления для Primary
   - Acceptable Loss (максимум 1 персона) — осознанно теряем
5. **Реализм:** Каждая персона строится на данных из research.md. "Боль" — из VOC. "Опыт" — из возражений. "Контекст" — из JTBD.
6. **Разнообразие:** Персоны отличаются по: возрасту, опыту, скептицизму, модели решений, стоп-факторам.

**Формат персон-карточки:**

```
PERSONA #{N}:
Имя: {имя}
Сегмент: {PRIMARY / SECONDARY / ACCEPTABLE_LOSS}
Возраст: {число}
Контекст: {2-3 предложения}
Текущая боль: {из VOC}
Предыдущий опыт: {что пробовал}
Скептицизм: {LOW / MEDIUM / HIGH / BURNED}
Модель решений: {ANALYST / SOCIAL / IMPULSIVE / METHODICAL}
Триггер покупки: {что нужно увидеть}
Стоп-фактор: {что заставит уйти}
```

**Показать персоны пользователю:** ОБЯЗАТЕЛЬНО. Перед dispatch покажи все карточки и спроси: **"Персоны для симуляции. Запускаем? (да / правки)"**

**Критерии вердикта:**
- **PASS:** все Primary → BUY/MAYBE (уверенность ≥ 6), retention Primary ≥ 70% на каждом сегменте

- **CRITICAL_FIX:** хотя бы 1 Primary → LEAVE или retention Primary < 60% на любом сегменте

#### 7.16.5. ШАГ 5: РЕШЕНИЕ И ДЕЙСТВИЕ

**По вердикту SIMULATION REPORT:**

- **PASS:** Показать отчёт → "Симуляция пройдена. Переходим к FINAL SELF-CHECK?"
- **NEEDS_FIX:** Показать отчёт + рекомендации → "Есть необязательные исправления. Исправить или принять как есть?"
  - Исправить → применить → перезапустить симуляцию (только проблемные персоны)
  - Принять → FINAL SELF-CHECK с пометкой `SIMULATION_OVERRIDE: {описание}` в state.md
- **CRITICAL_FIX:** Показать отчёт → "Текст не удерживает Primary. Обязательные исправления:" → применить → перезапустить ПОЛНУЮ симуляцию

**Лимит итераций:** максимум 2. После 2-го CRITICAL_FIX → эскалация: "Симуляция не прошла 2 раза. Варианты: A) Исправить и принять, B) Вернуться к STRATEGY, C) Принять как есть (ответственность пользователя)"

#### 7.16.6. FALLBACK RULES

1. **Agent tool недоступен:** 3 персоны in-context (PRIMARY-BURNED + PRIMARY-другая модель + SECONDARY)
2. **Target Segments (M) не определены:** Все персоны считаются PRIMARY. WARNING: "Секция M не заполнена. Рекомендуется заполнить."
3. **Research.md минимальный / отсутствует:** Персоны из brief.md + strategy.md. WARNING: "Персоны на ограниченных данных. Достоверность снижена."
