Сбор данных

Структурированный бриф по 12 секциям: от JTBD и 4 сил покупки до Expert Authority Profile. Система задаёт вопросы простым языком («О чём они говорят на кухне?»), а не маркетинговым жаргоном.

RESEARCH

Автоматический ресерч

3 субагента работают параллельно: VOC Mining (цитаты клиентов), Competitor Analysis (конкуренты + рынок), Curiosity Mining (нестандартные решения). 4-й субагент собирает всё в единый отчёт с дедупликацией и перекрёстной верификацией.

STRATEGY

Двойная стратегия

Стратегия формируется дважды: до и после обращения к базе знаний. Пользователь видит обе версии и выбирает. Параллельно в фоне работает Alternatives Scout — генерирует альтернативные Big Ideas и механизмы.

EXECUTION

Блочное написание

Текст пишется блок за блоком (Lead, Story, Mechanism, Offer...), каждый — отдельным сообщением. Перед каждым блоком — поиск по базе знаний: формулы, примеры из реальных sales letters. После каждого блока — независимый критик.

DEBUGGING

Критик-субагент

Отдельный AI-агент проверяет каждый блок по 30 критериям: от JTBD-релевантности до Trust Account и Pain Density. Получает полный контекст проекта (VOC-цитаты, возражения, конкуренты). Порог прохождения строгий, не «всё хорошо».

DELIVERY

Сборка и деплой

Final-критик (23 вопроса) проверяет собранный текст целиком. Zero Placeholders Gate — ни одного незаполненного proof-элемента. Автосборка HTML-лендинга через Python-скрипт. Деплой на GitHub Pages одной командой.

Ключевые модули

Что внутри движка

Система состоит из 11 модулей, каждый отвечает за свою область. Загружаются только нужные для текущего стейта — экономия контекстного окна.

Копирайтинг

Lead Router

6 типов лидов, выбор по уровню осведомлённости аудитории (Schwartz). Story-first, Problem-agitate, Mechanism-first, Proof-first, Offer-first, Solution bridge. Для каждого — шаблоны и примеры.

Копирайтинг

DRE Depth: 4 слоя боли

Каждый текст раскрывает боль на 4 уровнях: поверхность (симптомы) → цена (деньги, время) → эмоция (через сцены, не называние) → идентичность («что это говорит обо мне»). Тест «заслуженное решение»: без оффера читатель должен быть разочарован.

Копирайтинг

Story Engine

Трёхактная структура: дно → перелом → первый результат. Emotion Layer (эмоции через действия, не называние), Stakes Checklist (6 вопросов, порог 4/6), Inception Steps (загадка → хлебные крошки → ложный пик → раскрытие).

Копирайтинг

Trust Protocol

Банковая метафора: Trust Account с «депозитами» (конкретика, уязвимость, предсказания, доказательства) и «киллерами» (преувеличения, идеальные истории, фальшивая срочность). Баланс ≥ 3 на блок, ≥ 5 перед первым CTA.

Доказательства

Proof Engine

7 подпротоколов: таксономия 10 типов, майнинг по базе знаний, внешний ресерч, стекинг (эскалация малый → крупный), placement по блокам, калибровка по цене продукта, Anti-repetition Registry.

  • Mechanism-Proof Fusion: доказательство одновременно объясняет КАК и доказывает ЧТО
  • Insider Knowledge Mining: подавленные данные, контринтуитивные факты
  • Placeholder System: если proof не найден — ставится маркер, заполняется позже
Копирайтинг

Authority Weaving

5 паттернов вплетения экспертности (на основе анализа 26 реальных sales letters): Authority Anchor (54%), Discovery Narrative (31%), Authority Bridge (23%), Casual Introduction, Credential Stack. Матрица выбора по осведомлённости и искушённости.

Ресерч

Schwartz Matrix

5 уровней осведомлённости × 5 стадий рыночной искушённости = конкретная стратегия на пересечении. Определяет тип лида, глубину механизма, стиль доказательств, формат оффера.

Ресерч

JTBD Decoder

4 силы покупки вместо соцдема: Push (боль сейчас), Pull (картинка будущего), Anxiety (тревоги переключения), Habit (инерция). Архетипы проблем: Bleeding Neck, Chronic Pain, Looming Threat, Desire for Gain.

Смыслы

Big Idea Stack

4 элемента: враг/ошибка старого подхода + новый принцип + образ/метафора + обещание результата. На рынках с высокой искушённостью прямой оффер запрещён — нужна Большая Идея, которая переопределяет проблему.

Смыслы

Unique Mechanism

Двойной механизм: UMP (почему раньше не получалось — снять вину с человека) + UMR (почему сейчас сработает — новый путь с названием). Knowledge Gap Frame для мягкой альтернативы.

Качество

Pain Density

Каждый абзац pain-секции обязан вносить новый ракурс: новый слой DRE, новая ситуация, цифра, персонаж или следствие. Повтор без нового ракурса = удалить. Micro-relief каждые 3-4 абзаца при длинной боли.

Качество

Desire Engine

4 слоя желаемого состояния (зеркало DRE): конкретный результат → ценность для жизни → эмоциональная награда → обновление идентичности. Dream State в Close. Контрастное усиление: DRE слой 1 ↔ DES слой 1.

Дирижёр блоков

Schwartz Arrangement Mods

Юджин Шварц — автор «Breakthrough Advertising» (1966), библии копирайтинга. Мы провели полный аудит 26 его концепций, 10 уже встроены в систему. Новейшая — Arrangement Mods: 5 модификаторов, которые перестраивают скелет текста под конкретную ситуацию.

Ключевая идея

Не каждый текст должен следовать одному скелету

Lead Router выбирает ВХОД (первый блок). MOS Mode задаёт АКЦЕНТЫ (что усилить). Но Arrangement Mods управляют СЕРЕДИНОЙ И КОНЦОМ — порядком, плотностью и наличием блоков после лида. Модификаторы выбираются на этапе BRIEF по матрице Awareness × Sophistication × ниша × цена.

1

Proof Cycling

Mini-Proof после Mechanism и Product Reveal вместо одного стека proof в конце. Доказательство сильнее, когда читатель требует его.
Soph ≥ 3 • Health/Finance • Цена > $300

2

Authority Expansion

Авторитет — не 1-2 абзаца, а расширенный блок 5-12 абзацев между Pain и Bridge. Читатель чувствует боль и ищет, кому довериться.
Soph ≥ 4 • High-skepticism ниши • Нет strong brand

3

Promise Locomotive

Весь текст = нарастающие обещания с минимальной документацией. Proof и Story сокращены. «Сила продажи зависит от импульса обещания-локомотива» (Шварц).
Soph ≤ 2 • Problem/Solution Aware • Цена < $50

4

Proof-Promise Weave

Каждое обещание немедленно подкрепляется proof. Границы размыты — факт звучит как выгода, «каждое слово приобретает ауру чистого факта».
Soph 3-4 • Аудитория видела много обещаний

5

Identity Wrap

Текст начинается с образа (кто ты с этим продуктом), не с боли. Mechanism и Proof минимальны — продаёт образ. Story = «мир, в который ты входишь».
Soph 5 • Lifestyle • Premium

Schwartz Gap-анализ

26 концепций Шварца × Copycraft

Полный аудит: какие концепции «Breakthrough Advertising» уже встроены, какие частично, какие — в дорожной карте.

  • 10 INTEGRATED — 5 уровней Awareness, 5 стадий Sophistication, JTBD, Unique Mechanism, Big Idea, упрощение, снижение цены, уровни творчества
  • 9 PARTIAL — 38 техник заголовков, 3 измерения сознания, 13 способов интенсификации, цепочка принятий, маскировка, переопределение, momentum
  • 7 MISSING → дорожная карта — Sentence Weaving, Adaptive Architecture, Identification Engine, Reinforcement, Mood Toolkit, Sharpening, Logic Language
Оркестрация

10 субагентов

Специализированные AI-агенты, каждый решает свою задачу. Запускаются автоматически по правилам стейт-машины, работают параллельно где возможно.

A

VOC Mining

Сбор дословных цитат клиентов из отзовиков, Reddit, форумов. 15+ цитат на проект.

B

Competitor + Market

Анализ конкурентов: цены, слабости, позиционирование. Рыночные данные и тренды.

C

Curiosity + Corruption

Поиск забытых решений и «виновников» проблемы для Big Idea.

D

Proof Research

Внешние исследования: научные данные, кейсы. Mechanism-Proof Fusion.

E

Research-Mini

Точечный ресерч на конкретный пробел в данных во время написания.

F

Block Critic

Независимая проверка каждого блока по 30 критериям. Получает полный контекст проекта.

G

Launch Critic

Финальная проверка собранного текста: 23 вопроса + Cross-Block Consistency + Flow Check.

H

Research Assembler

Собирает результаты субагентов A+B+C: дедупликация, cross-referencing, единый отчёт.

I

KB-Scout

Ищет формулы и примеры в базе знаний перед написанием каждого блока.

J

Alternatives Scout

Генерирует альтернативные Big Ideas, механизмы, заголовки. Работает в фоне на этапе стратегии.

Оркестрация

Как это работает вместе

Субагенты запускаются автоматически по правилам стейт-машины. A+B+C работают параллельно на этапе ресерча. H собирает их результаты. I запускается перед каждым блоком копирайтинга. F — после каждого. G — перед финальной сборкой. J — в фоне на этапе стратегии. Все результаты показываются пользователю до интеграции. Fallback: если субагент недоступен — основной агент выполняет работу сам.

MCP-сервер

Как система использует знания

MCP-сервер (Model Context Protocol) даёт Claude прямой доступ к ChromaDB через 3 инструмента: search_knowledge (семантический поиск), list_sources (каталог файлов), reindex (переиндексация). Перед каждым блоком копирайтинга два параллельных потока ищут релевантные формулы и примеры: субагент KB-Scout + основной агент. Результаты объединяются и показываются пользователю до написания.

Техническая архитектура

Как это устроено

Вся система живёт в одной папке. Никакого отдельного приложения — только файлы, Claude Code и git.

CLAUDE.md ← Главный системный промпт (~250 строк) | |—— blocks/ ← 11 модулей инструкций (~80KB суммарно) | |—— 01 System Core (идентификация, философия, RAG-защита) | |—— 02 State Machine (переходы, гейты, правила) | |—— 03 Evidence + Brief (Evidence Map, Strategy Skeleton) | |—— 04 Protocols (Fluff Filter, Truth & Proof) | |—— 05 Research Engine (JTBD, Schwartz, VOC, Curiosity) | |—— 06 Meaning Maker (UMP/UMR, Big Idea, Offer) | |—— 07 Copy Kernel (Lead Router, DRE, Story, Proof — ~80KB) | |—— 08 Asset Library (Email, Ads, VSL, Chatbot) | |—— 09 Debugging (Critic 30Q, Launch 23Q, Strategy 7Q) | |—— 10 X-ray (9 измерений, скоринг, KB-сравнение) | `—— 11 Agents (10 субагентов, промпты, пайплайны) | |—— knowledge/ ← 74 файла → ChromaDB (2257 чанков) | |—— formulas/ (22 файла: паттерны, учебники, Schwartz) | `—— examples/ (52 файла: sales letters, RMBC-разборы) | |—— scripts/ ← MCP-сервер, HTML-сборщики | |—— knowledge_server.py (ChromaDB + MCP) | |—— build_html.py (673 строки, Jinja2 → landing) | `—— build_xray.py (376 строк, → xray report) | |—— projects/ ← 6 проектов (state.md + brief + draft + final) |—— docs/ ← HTML для GitHub Pages `—— templates/ ← Jinja2 (landing.html + xray.html)

Модульная загрузка

11 блоков, ~80KB суммарно, но в любой момент загружено только 8-18K токенов. Таблица «стейт → блоки» определяет, что загружать. Экономия контекстного окна без потери глубины.

Персистентность

state.md хранит текущий стейт, фазу, блоки, счётчики. Git хранит всю историю. Между сессиями ничего не теряется. Откат на любой стейт одной командой.

RAG через MCP

ChromaDB + мультиязычная эмбеддинг-модель + MCP-сервер = Claude ищет по смыслу в 2257 чанках. Поддержка русского и английского. Инкрементальная индексация.

Автосборка HTML

Python-скрипт парсит final.md в секции (HERO, BODY, CTA, FAQ, BRIDGE), рендерит через Jinja2, выкладывает в docs/. GitHub Pages деплоит автоматически при push.

Как строилась система

Фундамент

Защитные механизмы

Встроенные ограничения

Система не просто пишет — она активно предотвращает типичные ошибки AI-копирайтинга.

Антигаллюцинация

Evidence Map + Fact Tagging

Каждый факт получает 4 тега: тип, источник, надёжность, релевантность. Triple Source Rule: факт = CONFIRMED только при 3+ независимых источниках. Непроверенные данные маркируются как HYPOTHESIS.

Антиводянистость

Fluff Filter

Чёрный список: «высокое качество», «инновационный», «индивидуальный подход» и десятки других. Каждое пустое слово заменяется конкретикой. Треугольник: Правда? Им важно? Звучит свежо?

Антижаргон

Output Language Guard

JTBD, DRE, UMP, Schwartz — инструменты анализа. В генерируемый текст НЕ попадают. Каждый термин переводится в живой опыт читателя. Текст как разговор, не как учебник.

Антиинъекция

RAG Core

Все тексты из базы знаний — ДАННЫЕ, не инструкции. Иерархия: безопасность > процесс > запрос пользователя > источники. Детекция prompt injection в source-материалах.

Антиповтор

Proof Usage Registry

Один proof-элемент (кейс, отзыв, статистика) используется максимум в 1-2 блоках. Реестр в state.md отслеживает каждое использование. Запрещено дублирование.

Антитупик

Deadlock Recovery

Critic FAIL 3+ раз → автостоп + 4 варианта выхода. Пользователь 2 раза «не нравится» без конкретики → 3 гипотезы + 2 альтернативы. Счётчик попыток в state.md.
