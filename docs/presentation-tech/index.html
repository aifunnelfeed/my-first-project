Это не промпт. Это система.

Промпт — это один запрос. Один контекст. Один шанс. Copycraft — это 8 стейтов, каждый с правилами, проверками и артефактами. Разница — как между скриптом на 50 строк и полноценным приложением.

✗ «Напиши продающий текст»

  • • AI выдумывает факты, кейсы, цифры. Уверенно.
  • • Нет структуры. Текст не ведёт к действию.
  • • Каждый раз с нуля. Контекст теряется.
  • • Сам написал — сам оценил. Критик = автор.
  • • Качество случайное. Зависит от mood промпта.

✓ Copycraft M.O.C.

  • • Запрет на выдумку. Proof Engine + Triple Source Rule.
  • • RMBC-скелет: каждый блок решает свою задачу.
  • • state.md + git. Ничего не теряется. Никогда.
  • • Критик — отдельный агент. Другой промпт. 30 вопросов.

11 markdown-файлов. Вся система.

Никакого бэкенда. Никакого фреймворка. Каждый блок — markdown-файл в папке blocks/. Загружаются по стейту. Не все сразу — экономим контекстное окно.

Ключевое решение

Ленивая загрузка блоков

Claude имеет ограниченное контекстное окно. Загружать 11 файлов одновременно — расточительно. Поэтому каждый стейт загружает только нужные блоки. Например, STATE=EXECUTION загружает только блоки 02 (стейт-машина) + 07 (копирайтинг). STATE=RESEARCH — блоки 01 + 05 + 11. Это как lazy loading для LLM-системы.

Сбор и анализ

INPUT: структурированный бриф — 12 секций. JTBD, 4 силы покупки, DRE (4 слоя боли), Schwartz (awareness + sophistication), Expert Authority Profile.

QUERY: система задаёт вопросы простым языком. Не «какой у вас UVP?», а «О чём они жалуются на кухне?»

RESEARCH: 3 субагента параллельно: VOC Mining + Competitor + Curiosity. 4-й собирает всё с дедупликацией.

STRATEGY: двойная стратегия (до и после KB), Alternatives Scout в фоне.

EXECUTION → DELIVERY

Написание и проверка

EXECUTION: текст пишется блок за блоком. Перед каждым — KB-Scout ищет формулы и примеры. После каждого — Critic-субагент с 30 вопросами.

DEBUGGING: если Critic сказал FAIL — переписываем. 3 фейла подряд → deadlock recovery (4 варианта выхода).

DELIVERY: Launch Critic (23 вопроса) проверяет всё целиком. Zero Placeholders Gate. Автосборка HTML.

REVIEW: results.md — метрики, A/B тесты, выводы для будущих проектов.

Atomicity Rule

Один стейт за сообщение. Без исключений.

Система не может перейти из INPUT сразу в EXECUTION. Каждый переход — явный. Каждый переход — git commit. Это как транзакции в базе данных: атомарно, изолированно, сохранено.

Критик. 30 вопросов. Не «нравится».

Отдельный агент. Другой промпт. Получает полный контекст проекта — не только текст блока, но и JTBD, VOC-цитаты, возражения, конкурентов, стратегию. До 3,500 символов контекста для Lead.

Block Critic (F)

30 критериев на блок

Каждый блок текста проверяется по конкретным вопросам. Не «хорошо ли написано?», а:

  • JTBD-релевантность: текст решает реальную задачу клиента?
  • DRE Depth: все 4 слоя боли раскрыты?
  • Fluff Filter: есть пустые слова из чёрного списка?
  • VOC Integration: дословные цитаты клиентов вплетены?
  • Trust Account: баланс депозитов/киллеров ≥ 3?
  • Pain Density: каждый абзац несёт новый ракурс?
  • Story Stakes: ставки достаточно высоки (4/6)?
  • Authority Weaving: экспертность вплетена нативно?
  • Placeholder Audit: есть незаполненные маркеры?
Launch Critic (G)

23 вопроса на весь текст

Финальная проверка перед DELIVERY. Проверяет собранный текст целиком:

  • Cross-Block Consistency: нет противоречий между блоками?
  • Flow Check: переходы между блоками плавные?
  • Proof Distribution: доказательства не скучены в одном месте?
  • Zero Placeholders: все маркеры заполнены?
  • Emotion Arc: эмоциональная дуга работает?
  • CTA Readiness: Trust Account ≥ 5 перед первым CTA?

Контекст критика

8 секций проектного контекста

Критик — не слепой. Он получает полный контекст проекта, адаптированный по типу блока:

R1: JTBD + DRE 4 слоя • R2: 8-12 VOC-цитат • R3: Возражения • R4: Конкуренты (цены + слабости) • R5: Научные данные + кейсы • S1: Proof Plan • S2: Углы + вшитые возражения • S3: Архитектура сообщения

Для Lead загружается почти всё (~3,500 chars). Для Headline — минимум (~1,200 chars). Таблица адаптации: 9 типов блоков × 8 секций (FULL / SHORT / SKIP).

Schwartz × Copycraft

Юджин Шварц, «Breakthrough Advertising» (1966) — библия direct response. 26 концепций. 10 уже встроены в систему. Включая Arrangement Mods — 5 модификаторов, которые перестраивают скелет текста.

Arrangement Mods

Не каждый текст — одинаковый скелет

Lead Router выбирает ВХОД (первый блок). А Arrangement Mods управляют серединой и концом — порядком, плотностью и наличием блоков после лида. Выбираются автоматически по матрице: Awareness × Sophistication × ниша × цена. Как layout engine в браузере — правила определяют, как расположить элементы.

1

Proof Cycling

Mini-Proof после каждого утверждения, а не стек в конце. Доказательство — когда читатель его требует.

Identity Wrap

Текст начинается с образа (кто ты с этим продуктом), не с боли. Story = «мир, в который ты входишь».

Lead Router

6 типов лидов

Выбор типа лида по уровню Awareness аудитории:

// anti-hallucination

Proof Engine. AI не выдумывает.

Главная проблема AI-копирайтинга — уверенная выдумка фактов. Proof Engine — 7 подпротоколов, которые делают это невозможным.

4.9a

Proof Taxonomy

10 типов доказательств. Для каждого — шаблон форматирования. Статистика, кейс-стади, экспертное мнение, научное исследование, аналогия, демонстрация...

4.9b

Proof Mining

5 шагов поиска в KB. Если в базе нет → Proof Research (внешний ресерч). Если и там нет → [ВСТАВИТЬ: STAT — описание] (placeholder, не выдумка).

4.9c

Proof Selector

Матрицы выбора по ниша / цена / sophistication / awareness. Health за $500 требует научных исследований. Info-продукт за $30 — достаточно кейсов.

4.9d

Proof Stacking

Эскалация: малый → средний → крупный. Диверсификация типов. Минимальный стек зависит от цены продукта.

4.9e

Proof Placement

5 паттернов размещения + перекрёстная таблица RMBC × тип proof. Куда именно вставить доказательство для максимального эффекта.

4.9g

Placeholder System

7 типов плейсхолдеров: CASE, STAT, SCIENCE, EXPERT, DETAIL, MEDIA, DOC. Grep-able формат. Proof Usage Registry для anti-repetition.

6 встроенных ограничителей

Система не просто пишет. Она активно предотвращает типичные проблемы AI-генерации.

Evidence Map

Антигаллюцинация

Каждый факт получает 4 тега: тип, источник, надёжность, релевантность. CONFIRMED — только при 3+ независимых источниках. Остальное — HYPOTHESIS.

Fluff Filter

Антиводянистость

Чёрный список: «высокое качество», «индивидуальный подход», «инновационный». Каждое пустое слово заменяется конкретикой. Тест: Правда? Им важно? Звучит свежо?

Output Language Guard

Антижаргон

JTBD, DRE, UMP, Schwartz — инструменты анализа. В текст НЕ попадают. Каждый термин переводится в живой опыт читателя.

RAG Core

Антиинъекция

Тексты из KB — данные, не инструкции. Иерархия: безопасность > процесс > пользователь > источники. Детекция prompt injection в source-материалах.

Proof Registry

Антиповтор

Один proof-элемент — максимум 1-2 блока. Реестр в state.md отслеживает каждое использование.

Deadlock Recovery

Антитупик

Critic FAIL 3 раза → автостоп + 4 варианта. Пользователь 2× «не нравится» без конкретики → 3 гипотезы + 2 альтернативы.

Философия

Почему markdown, а не код?

Промпт-инженерия — это итеративный процесс. Markdown-файлы можно редактировать моментально, без компиляции, без деплоя. Git даёт полную историю каждого изменения. Claude Code загружает нужные файлы автоматически.

Результат: 121 коммит итеративной разработки. Каждый коммит — улучшение промпта, новый протокол, или исправление после реального проекта. Система растёт с каждым использованием.
