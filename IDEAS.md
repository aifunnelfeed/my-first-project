# Copycraft — Идеи для развития

Файл для фиксации идей, обсуждённых в сессиях. Не TODO, а пространство для мышления.

---

## 1. Мультиагентная архитектура

**Суть**: Разделить текущего единого агента на специализированных агентов с оркестратором.

**Агенты**:
- **Orchestrator** — Claude Code с CLAUDE.md, управляет процессом, общается с пользователем
- **Researcher** — Perplexity API, только сбор данных (не анализ)
- **Copywriter** — Claude API с промптом из блоков 07/08, только пишет
- **Critic** — Claude API с отдельным промптом (блок 09), только критикует

**Ключевое**:
- Critic отделён от Copywriter — независимая оценка, нет предвзятости "автор рецензирует себя"
- Researcher на Perplexity — свежие данные, а не знания из обучения
- Начинать с отделения Critic (самый большой выигрыш), затем Researcher

## 2. Watchdog-система: мониторинг конкурентов + рекомендации

**Суть**: Автоматический агент, который следит за рынком и присылает рекомендации при изменениях.

**Цепочка**:
```
Триггер (плохая конверсия / расписание / вручную)
  → Researcher (Perplexity API): ищет конкурентов, офферы, тренды
  → Recommender (Claude API): сравнивает с текущим проектом, даёт рекомендации
  → Доставка: Telegram / email
```

**Ключевое**:
- Триггер "плохая конверсия" требует порога: CR < X% в течение Y дней, иначе шум
- Recommender получает контекст проекта (strategy.md, final.md, results.md) — без контекста рекомендации будут generic
- Агент рекомендует, человек решает — автопатчинг лендинга недопустим
- Реализация: n8n (визуально, без кода) / cron + Python-скрипт / GitHub Actions

## 3. Рентген-режим (X-Ray View)

**Суть**: Веб-визуализация финального текста с интерактивной разметкой — почему каждый элемент работает.

**Три режима просмотра**:
- **Читатель** — чистый текст, как для конечного клиента
- **Рентген** — текст + цветовыделение триггеров + аннотации после каждого блока
- **Обучение** — пошаговый разбор: "почему выбран этот тип лида, этот механизм"

**Пример разметки**:
- Цветовыделение внутри текста: "эта фраза вызывает любопытство — триггер Шугермана #7 (Specificity)"
- После каждого блока: тип блока, awareness level, critic score, почему блок сильный

**Техническая реализация**:
- При DELIVERY Copycraft генерирует JSON с метаданными (блок, сегменты, триггеры, аннотации)
- Веб-фронтенд (React) рендерит текст с интерактивными аннотациями

**Ключевое**:
- Ни у кого нет ничего подобного — это главный дифференциатор
- Работает как продающий инструмент: маркетолог видит глубину анализа и хочет такую систему
- Каждый рентген — готовый контент для соцсетей (виральность встроена в формат)
- Открывает образовательную линейку монетизации: библиотека рентгенов, курсы, разбор чужих текстов

## 4. Copycraft как продукт: путь к SaaS

**Суть**: Эволюция от личного инструмента до платформы с сетевым эффектом.

**Уровни**:
1. **Инструмент** (сейчас) — один пользователь, потолок $10-30K/мес
2. **Агентство с суперсилой** — 3-5 копирайтеров внутри системы, потолок $50-150K/мес
3. **SaaS** — подписка $200-500/мес, 1000 клиентов = $2-6M/год
4. **Платформа с данными** — Conversion Intelligence, сетевой эффект

**Conversion Intelligence (ядро бизнеса на уровне 4)**:
- Каждый пользователь генерирует results.md → тысячи A/B тестов → база "что работает"
- Система знает: какой тип lead работает в нише X, какие механизмы для аудитории Y
- Новый пользователь получает рекомендации на основе тысяч чужих проектов
- Эти данные — moat, который невозможно скопировать

**Ключевое**:
- Промпты скопируют за неделю, данные конверсий 10,000 проектов — не скопирует никто
- Начинать с кейсов: 5-10 реальных проектов с метриками через Copycraft
- Не строить SaaS до валидации — сначала агентство, потом платформа

## 5. Мета-воронка: Copycraft продаёт Copycraft

**Суть**: Использовать саму систему для создания продающих материалов о системе.

**Воронка**:
```
Лонгрид (продаёт проблему + механизм)
  → VSL (живая демонстрация процесса, 12-15 мин)
  → Рентген-пример (интерактивный пруф)
  → CTA: запись на демо / доступ / waitlist
```

**Мета-пруф**: "Лендинг, который вы сейчас читаете, создан внутри Copycraft. Вот коммит."

**VSL — ключевые моменты**:
- Показать FAIL от Critic — контринтуитивно, но это самый убедительный момент
- Все AI-инструменты показывают генерацию, никто не показывает контроль качества
- FAIL → FIX → PASS = доказательство, что это не ChatGPT-обёртка

**Ключевое**:
- Два отдельных проекта в Copycraft: `copycraft-long` (landing) + `copycraft-vsl` (vsl)
- VSL не повторяет лонг, а продолжает — зритель уже прочитал текст
- Демо вместо прямой продажи — сложный продукт, длинный цикл сделки

## 6. Автопубликация: из текста — в живой лендинг

**Суть**: Дополнительный шаг после DELIVERY — Claude собирает HTML из final.md и деплоит на хостинг. Привязал домен — и лендинг живой.

**Цепочка**:
```
final.md → Claude генерирует HTML (шаблон + Tailwind CDN)
  → коммит в GitHub-репо
  → Cloudflare Pages / Vercel автодеплоит
  → домен привязан один раз → сайт обновляется при каждом пуше
```

**Подход к дизайну**:
- Claude не дизайнит с нуля — наполняет готовый шаблон контентом
- Один качественный Tailwind-шаблон лендинга в проекте — переиспользуется
- Лендинги прямого отклика специально простые: белый фон, чёрный текст, одна акцентная кнопка — сложный дизайн мешает конверсии

**Ключевое**:
- Не нужен Lovable / Bolt.new / отдельный сервис — Claude уже умеет генерировать HTML + Tailwind
- Не нужен свой хостинг — Cloudflare Pages / Vercel / Surge бесплатно, SSL из коробки
- Не строить конструктор сайтов — это не Tilda, сила в готовом результате без конструктора
- v0.dev (Vercel) есть как опция для улучшения визуала через API, но для direct response лендингов избыточен
- Ценность: продаёшь не "текст", а готовый инструмент для заработка — клиент пришёл с брифом, ушёл с работающим сайтом

## 7. Стратегия продвижения

**Главный принцип**: Не продавай продукт. Показывай процесс и результаты. Продукт продаст себя сам.

**Telegram-канал "Рентген копирайтинга"** (основной канал):
- Разбор чужих лендингов (что слабо и почему)
- Процесс изнутри (серия постов на один проект)
- Один приём + пример применения + результат
- Метрики из results.md
- Частота: 3-4 поста в неделю

**YouTube / короткие видео**:
- Скринкасты процесса ("AI написал лендинг — смотрю как эксперт")
- Shorts: один приём = быстрый разбор до/после
- Показывать FAIL от Critic — завораживает

**Партнёрства с экспертами**:
- Бесплатный лендинг через Copycraft в обмен на кейс + упоминание аудитории
- Целиться в экспертов с аудиторией 10-50K
- 5 партнёрств = 5 кейсов + 50-250K охвата

**Ключевое**:
- Не называть "AI-копирайтер" — это commodity. Позиционирование: "система, которая выстраивает текст по принципам прямого отклика и проверяет каждый блок перед публикацией"
- Нельзя говорить "гарантирует конверсию" — продаём методологию + контроль качества, результаты показываем кейсами как факт, не как обещание
- Не запускать рекламу до кейсов
- Первые шаги: один реальный проект → Telegram-канал (5 постов) → одно партнёрство с экспертом

## 8. SEO-агент: контент-завод для бесплатного трафика

**Суть**: Отдельный агент (не Copycraft), который генерирует SEO-контент для привлечения органического трафика. SEO-статьи перелинковываются на продающие тексты Copycraft.

**Почему отдельный агент**: Copycraft заточен под конверсию (триггеры, офферы, прямой отклик). SEO-текст — другая задача: LSI-ключи, структура под поисковики, E-E-A-T. Смешивать нельзя.

**Архитектура пайплайна**:
```
Airtable / Google Sheets (база ключевиков + кластеры + статусы)
  → SEO-агент (Claude API, отдельный промпт)
  → Человек (ревью, экспертный слой)
  → Автопубликация (Cloudflare Pages / WordPress)
  → Перелинковка → лонгрид Copycraft (конверсия)
```

**Типы контента по intent**:
- Tier 1 (высокий intent): "как написать продающий лендинг", "как увеличить конверсию лендинга"
- Tier 2 (средний intent): "триггеры Шугермана примеры", "формула AIDA примеры на русском"
- Tier 3 (сравнения): "ChatGPT для копирайтинга — работает ли", "AI копирайтер сравнение"

**Киллер-фича: рентген-разборы как уникальный контент**:
- Обычная статья "5 триггеров Шугермана" — таких тысячи
- Твоя статья "5 триггеров Шугермана — рентген реального лендинга с конверсией 4.2%" — такого ни у кого нет
- Рентген из идеи #3 становится уникальным контентом, который невозможно скопировать
- Именно уникальные данные отличают успешные контент-заводы от мёртвых

**Инструменты**:
| Этап | Инструмент |
|------|-----------|
| Планирование | Airtable (ключевики, кластеры, статусы) |
| Оптимизация | Surfer SEO / Frase (LSI-ключи, SERP-анализ) |
| Генерация | Claude API (SEO-агент, отдельный промпт) |
| Уникальность | Copycraft (рентген-разборы реальных проектов) |
| Ревью | Человек (экспертный слой — обязателен для E-E-A-T) |
| Публикация | n8n → Cloudflare Pages / WordPress |
| Мониторинг | Google Search Console |
| Прунинг | Ежемесячно удалять страницы без трафика |

**Референсы с доказанной эффективностью**:
- Wise: 260K программатик-страниц → 60M визитов/мес (уникальные live-данные на каждой странице)
- Zapier: 25-50K страниц → 16M визитов/мес (каждая комбинация интеграций = страница)
- Тинькофф Журнал: 2.5M визитов/мес, 55% из SEO (лучший бренд-медиа в RU)
- Diggity Marketing: выручка с $166K до $491K/мес через AI + Make.com + Google Sheets
- Healthline: 96M визитов/мес, 200+ статей/мес (каждую проверяет врач с именем)

**Почему контент-заводы проваливаются** (Google Dec 2025 Core Update):
- Массовый AI-контент без эксперта: -87% трафика
- Менее 30% уникального контента на странице — санкции
- Шаблонные страницы без дифференциации — смерть

**Формула успеха**: уникальные данные + реальная польза + экспертный слой + постепенный запуск

**Ключевое**:
- SEO — дополнение к основным каналам, не замена. Результат через 3-6 мес
- Не штамповать 100 generic-статей, а сделать 10-15 якорных — лучших по теме в рунете
- Обязателен экспертный слой (ты) — без него Google накажет
- Начать с 5 тестовых статей, проверить ранжирование, потом масштабировать
- Стратегия: SEO-агент приводит трафик → Copycraft конвертит

## 9. Системные фиксы копирайтерского ядра

**Контекст**: При анализе `blog-growth/final.md` глазами скептического клиента выявлены 4 пробела в протоколах. Проблемы системные — проявятся в любом проекте.

### 9a. FAQ_DEDUP — антидубликат FAQ

**Проблема**: FAQ пересказывает основной текст (те же факты, метафоры, proof). Нет правила "FAQ = новая информация".

**Решение**: Секция 4.8a в Block 07 — `[FAQ_DEDUP_V1]`. Запрет на повтор статистик/метафор/proof из основного текста. Каждый ответ FAQ обязан содержать новый угол, новый proof или новую конкретику о продукте. Тест: убери из ответа FAQ всё, что уже сказано выше — если осталось < 50%, переписать.

### 9b. REPETITION_CONTROL — контроль повторов

**Проблема**: Элементы повторяются 5-6 раз (факт "847 комментариев" — 5 раз, "15 минут" — 6 раз). К третьему разу скептик чувствует манипуляцию, а не убеждение.

**Решение**: Секция 4.0c в Block 07 — `[REPETITION_CONTROL_V1]`. Любой элемент (факт, статистика, цитата, метафора, proof) — максимум 2 раза в тексте. Идеал — 1 раз. Core Promise — исключение (Headline + Close + CTA). Callback допустим только если добавляет новый контекст.

**Обязательная проверка в двух местах**:
- Critic Mode (Block 09) — новый вопрос Q28
- STATE=REVIEW (Block 02) — Repetition Audit как первый шаг: таблица всех повторов, элементы с 3+ → исправить

### 9c. PROMISE_PRODUCT_GAP — разрыв обещание-продукт

**Проблема**: Critic проверяет proof, mechanism, story — но не проверяет, продаёт ли текст больше, чем продукт может дать. Текст обещает "300 000 ₽/мес", продукт — 3 урока по съёмке Reels. Разрыв огромный, критик молчит.

**Решение**: Новый вопрос Q29 в Critic Mode + Q22 в Launch Checklist. Тест: выписать 3 самых крупных обещания → для каждого проверить — может ли продукт (по brief.md) это объективно дать? Если обещания подкреплены 1 кейсом → пометить [СЛАБАЯ ДОКАЗАТЕЛЬНАЯ БАЗА].

### 9d. ENTITY_FOCUS — антиконкуренция сущностей

**Проблема**: Текст может вводить конкурирующие сущности: две развёрнутые истории, два механизма, два обещания разного масштаба — и фокус размывается.

**Решение**: Секция 4.0d в Block 07 — `[ENTITY_FOCUS_V1]`. Одна ось: 1 Core Promise, 1 главная история/герой, 1 UMR, 1 враг (UMP), 1 метафора-якорь. Всё остальное — поддержка оси. Конкурирующие сущности запрещены. Новый вопрос Q30 в Critic + Q23 в Launch.
