## РАЗДЕЛ 2: ГЕНЕРАЦИЯ ПЕРСОН

### 2.1. 4 ТИПА ПЕРСОН
КОД ДОСТУПА: [PERSONA_TYPES_V1]

| Тип | Описание | Количество | Источник |
|-----|---------|-----------|----------|
| **PRIMARY** | Основной сегмент ЦА. Максимально близок к Target Segments (M) | 2-4 | Job Map (Primary Job) + Audience Depth |
| **SECONDARY** | Дополнительные сегменты. Другая работа или другой контекст | 1-3 | Job Map (Secondary Jobs) |
| **EDGE CASE** | Нетипичный покупатель. Крайний случай, но реалистичный | 1-2 | Decision Journey (необычный путь) |
| **SKEPTIC** | Высокое сопротивление. Обжёгся, не верит, ищет подвох | 1-3 | Objection Tree (P1) + Failed Methods |

### 2.2. КАРТОЧКА ПЕРСОНЫ
КОД ДОСТУПА: [PERSONA_CARD_V1]

```markdown
### Персона {N}: {Имя}

**Тип:** {PRIMARY / SECONDARY / EDGE CASE / SKEPTIC}
**Сегмент:** {из Target Segments}

**Профиль:**
- Возраст / контекст: {не соцдем, а жизненная ситуация}
- Job: {на какую работу нанимает продукт}
- Awareness: {уровень 1-5}
- Sophistication: {уровень 1-5}

**Текущие убеждения (из Belief Map):**
1. {убеждение} — Сила: {1-5}
2. {убеждение} — Сила: {1-5}
3. {убеждение} — Сила: {1-5}

**Главное возражение:** {из Objection Tree}
**Этап Decision Journey:** {на каком этапе находится}
**Failed Methods:** {что уже пробовал — 1-2 метода}
**Emotional State:** {доминирующая эмоция}
```

**ПРАВИЛА:**
1. Каждая персона = конкретный человек с именем, ситуацией, историей. НЕ абстрактный "сегмент B".
2. Убеждения берутся из Belief Map (Слой 1). Минимум 2 на персону.
3. Если в synthesis.md не хватает данных для персоны — пометить `[SIM-PERSONA]` и обосновать.

### 2.3. ADVERSARIAL PERSONA PROTOCOL
КОД ДОСТУПА: [ADVERSARIAL_PERSONA_V1]

Скептики — специальный подтип, созданный для стресс-теста аргументации.

**4 ТИПА СКЕПТИКОВ:**

| Тип | Характеристика | Ключевой вопрос | Что тестирует |
|-----|---------------|----------------|--------------|
| **BURNED** | Потратил деньги на аналог, не получил результат | "Чем это отличается от того, что я уже пробовал?" | Дифференциация, Failed Methods |
| **EXPERT** | Знает нишу, высокая Sophistication (4-5) | "Это просто маркетинг — покажите данные" | Proof, Evidence Map |
| **PRICE-SENSITIVE** | Считает каждую копейку, сравнивает с бесплатными альтернативами | "Почему я должен платить, если есть бесплатное?" | Value Stack, Offer |
| **CONTRARIAN** | Принципиально не доверяет продающим текстам | "Если это так хорошо — почему вы так агрессивно продаёте?" | Tone, Trust, Authority |

**ПРАВИЛО:** Минимум 1 BURNED (самый частый тип) + 1 любой другой. При DEEP — 2-3 разных типа.

## РАЗДЕЛ 3: ТРИ ТЕСТА СИМУЛЯЦИИ

### 3.1. ТЕСТ 1: PROBLEM RECOGNITION
КОД ДОСТУПА: [TEST_PROBLEM_RECOGNITION_V1]

**ВОПРОС:** Узнаёт ли персона свою проблему в нашей формулировке?

**ВХОД ДЛЯ ТЕСТА:** Job Map (Primary Job + PUSH/PULL), Scene Bank (PAIN-сцены), первый абзац Lead (если есть в synthesis)

**ШКАЛА:**

| Балл | Описание |
|------|---------|
| 5 | "Это точно про меня. Как будто подсматривали" |
| 4 | "Да, знакомо. У меня похожая ситуация" |
| 3 | "Частично. Некоторые моменты про меня, но не все" |
| 2 | "Вижу проблему, но формулировка не моя" |
| 1 | "Не узнаю себя. Это про кого-то другого" |

**3 КРИТЕРИЯ ОЦЕНКИ:**

| Критерий | Что оцениваем | Источник данных |
|----------|-------------|----------------|
| **Узнавание ситуации** | Видит ли себя в описании проблемы | Scene Bank + PUSH |
| **Язык резонанса** | Совпадает ли язык с его внутренним диалогом | VOC + Internal Dialogue |
| **Эмоциональный отклик** | Вызывает ли описание эмоцию | True Fears + Shock Events |

**ФОРМАТ ВЫВОДА (на персону):**

```markdown
#### Тест 1: Problem Recognition — {Балл}/5
- Узнавание ситуации: {да/частично/нет} — "{что именно узнал или не узнал}"
- Язык резонанса: {да/частично/нет} — "{какие фразы зацепили / какие чужие}"
- Эмоциональный отклик: {какая эмоция возникла}
- Что резонирует: {конкретно}
- Что не работает: {конкретно}
- Цитата персоны: "{внутренняя реакция}"
```

### 3.2. ТЕСТ 2: MECHANISM CREDIBILITY
КОД ДОСТУПА: [TEST_MECHANISM_CREDIBILITY_V1]

**ВОПРОС:** Поверит ли персона, что наш механизм/метод может решить проблему?

**ВХОД ДЛЯ ТЕСТА:** Mechanism Inputs (Unfair Advantage + Mode), Belief Map (Beliefs to Break), Evidence Map (FACTS с CORE relevance)

**ШКАЛА:**

| Балл | Описание |
|------|---------|
| 5 | "Логично. Вижу, почему это работает и чем отличается" |
| 4 | "Интересно. Готов попробовать, хотя есть вопросы" |
| 3 | "Может быть. Нужно больше доказательств" |
| 2 | "Сомневаюсь. Звучит как маркетинг" |
| 1 | "Не верю. Очередная пустышка" |

**3 КРИТЕРИЯ ОЦЕНКИ:**

| Критерий | Что оцениваем | Источник данных |
|----------|-------------|----------------|
| **Логика механизма** | Понятна ли причинно-следственная цепочка | Unfair Advantage (Слой 2) |
| **Дифференциация** | Видит ли отличие от того, что пробовал | Failed Methods + Competitor Analysis |
| **Доказательная база** | Достаточно ли evidence для доверия | Evidence Map (FACTS) |

**ФОРМАТ ВЫВОДА (на персону):**

```markdown
#### Тест 2: Mechanism Credibility — {Балл}/5
- Логика механизма: {понятна/частично/непонятна} — "{что именно (не)понял}"
- Дифференциация: {видит/частично/не видит} — "{от чего отличает или не отличает}"
- Доказательная база: {достаточно/частично/недостаточно} — "{что убедило / чего не хватает}"
- Возражения: {список конкретных возражений, возникших при тесте}
- Belief Shift: {какое убеждение из Belief Map сдвинулось / не сдвинулось}
- Цитата персоны: "{внутренняя реакция}"
```

### 3.3. ТЕСТ 3: OFFER ATTRACTIVENESS
КОД ДОСТУПА: [TEST_OFFER_ATTRACTIVENESS_V1]

**ВОПРОС:** Захочет ли персона купить при текущем позиционировании?

**ВХОД ДЛЯ ТЕСТА:** Objection Tree (топ-возражения), Decision Model, pricing из competitor analysis, Belief Map (Beliefs to Build)

**ШКАЛА:**

| Балл | Описание |
|------|---------|
| 5 | "Куда платить? Это именно то, что мне нужно" |
| 4 | "Скорее да. Нужна последняя деталь (гарантия / отзыв / цена)" |
| 3 | "Возможно. Буду сравнивать с альтернативами" |
| 2 | "Скорее нет. Не вижу достаточной ценности за эту цену" |
| 1 | "Точно нет. Не для меня / не верю / дорого" |

**3 КРИТЕРИЯ ОЦЕНКИ:**

| Критерий | Что оцениваем | Источник данных |
|----------|-------------|----------------|
| **Ценность vs цена** | Воспринимаемая ценность превышает цену | Value Equation (если есть), Pricing Landscape |
| **Снятие возражений** | Основные возражения адресованы | Objection Tree (P1, P2) |
| **Триггер действия** | Что заставит купить сейчас, а не потом | Decision Model + Urgency factors |

**ФОРМАТ ВЫВОДА (на персону):**

```markdown
#### Тест 3: Offer Attractiveness — {Балл}/5
- Ценность vs цена: {высокая/нормальная/низкая} — "{как оценивает соотношение}"
- Снятие возражений: {главное возражение снято? да/нет} — "{что осталось}"
- Триггер действия: {что заставит купить сейчас} — "{или почему отложит}"
- Что не хватает: {конкретно — гарантия / отзывы / демо / рассрочка}
- Готовность к покупке: {купит / отложит / откажется}
- Цитата персоны: "{внутренняя реакция}"
```

### 4.1. ПОРЯДОК ВЫПОЛНЕНИЯ
КОД ДОСТУПА: [SIMULATION_PIPELINE_V1]

```
synthesis.md (одобренный)
    │
    ├─ ШАГ 1: Генерация персон (главный агент)
    │   └─ Создать карточки по [PERSONA_CARD_V1]
    │   └─ Показать пользователю → одобрение
    │
    ├─ ШАГ 2: Dispatch субагентов (параллельно)
    │   ├─ W (Persona Simulator) × N — по одному на персону (PRIMARY + SECONDARY + EDGE)
    │   └─ V (Adversarial Persona) × M — по одному на скептика
    │
    ├─ ШАГ 3: Агрегация (главный агент)
    │   └─ Собрать scorecards → Vulnerability Map → Recommendations
    │
    └─ ШАГ 4: Отчёт
        └─ Показать пользователю → simulation_report.md
```

**ПРАВИЛО:** Шаг 2 запускается ТОЛЬКО после одобрения персон пользователем (Шаг 1). Пользователь может:
- Одобрить список → Шаг 2
- Убрать персону → скорректировать и продолжить
- Добавить персону → описать кратко, агент создаст карточку
- Изменить тип скептика → выбрать из 4 типов

### 4.2. FALLBACK (без Agent tool)

Если субагенты W/V недоступны — выполнить симуляцию in-context:
- Сократить до 3-5 персон + 1 скептик
- Выполнить 3 теста последовательно для каждой персоны
- Формат вывода тот же

## РАЗДЕЛ 6: ПРАВИЛА И ОГРАНИЧЕНИЯ

### 6.1. ПРАВИЛА СИМУЛЯЦИИ

1. **Честная симуляция.** Персона НЕ должна быть "удобной". Если данные synthesis говорят, что возражение сильное — персона БУДЕТ возражать.
2. **Consistency.** Убеждения персоны (из Belief Map) должны влиять на все 3 теста. Нельзя: верит что "все курсы развод" → Mechanism Credibility = 5.
3. **No salvation bias.** Не "спасай" низкие баллы. Если Offer = 2, значит 2. Это ценная информация.
4. **Traceability.** Каждый балл обоснован данными из synthesis.md — не интуицией.
5. **Adversarial integrity.** Скептик V должен атаковать РЕАЛЬНЫЕ слабости, а не соломенных людей.

### 6.2. CRITICAL STOPS (блокируют переход в VALIDATION)

| Условие | Действие |
|---------|---------|
| PASS rate < 50% | СТОП. Показать Vulnerability Map. Предложить: A) Backtrack в SYNTHESIS B) Скорректировать стратегию C) Продолжить с рисками |
| Любой PRIMARY с FAIL | СТОП. Основной сегмент не проходит. Обязательный backtrack или пересмотр. |
| Все скептики дали Mechanism ≤ 2 | WARNING. Механизм не убеждает критиков. Рекомендация: усилить Evidence Map. |

### 6.3. GIT

Формат коммита: `research({проект}): simulation — {N} personas, {M} skeptics, {PASS rate}%`
