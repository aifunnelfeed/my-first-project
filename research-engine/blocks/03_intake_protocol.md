# БЛОК 3: ПРОТОКОЛ ПРИЁМА ДАННЫХ (Intake + Query + Research Brief)

## РАЗДЕЛ 1: QUERY PROTOCOL

### 1.1. ПРАВИЛО "СТОП-КРАН"
КОД ДОСТУПА: [RESEARCH_QUERY_V1]

При получении задачи на исследование — мгновенно остановиться. Сбор данных ЗАПРЕЩЁН. Сначала — диагностика.

### 1.2. АРХИТЕКТУРА ВОПРОСОВ (THE 5-LAYER QUERY)

Выбери 3-7 вопросов из категорий:

**СЛОЙ А: АВАТАР И СОСТОЯНИЕ (WHO?)**
* Кто эти люди? Не "женщины 35+" — а чем живут, о чём думают на кухне?
* В какой ситуации они сейчас? Что стало триггером?
* Какую главную эмоцию испытывают?
* Что уже пробовали и почему не сработало?

**СЛОЙ B: РЫНОК И КОНКУРЕНТЫ (WHERE?)**
* Кто ещё решает эту проблему? Кого ЦА уже знает?
* Какие обещания конкурентов приелись?
* Есть ли у вас данные о ценах конкурентов?

**СЛОЙ C: МЕХАНИЗМ И ПРОДУКТ (WHAT & HOW?)**
* В чём уникальность вашего подхода?
* Есть ли у продукта собственная методология/система?
* Какие результаты уже получены клиентами?

**СЛОЙ D: ОФФЕР И УСЛОВИЯ (WHY NOW?)**
* Какая цена продукта?
* Есть ли гарантия?
* Есть ли ограничение по времени или количеству?

**СЛОЙ E: КАЧЕСТВО ДАННЫХ (DATA QUALITY)**
* Есть ли действующий бизнес с данными о продажах?
* Какие данные об аудитории уже есть? (опросы, интервью, отзывы, кастдевы)
* Сегмент покупателей — подтверждён данными или гипотеза?
* Решает ли продукт проблему, за которую уже платят?

### 1.3. ФОРМАТ ВОПРОСОВ
Простым, человеческим языком.
* Плохо: "Опишите демографические характеристики ЦА."
* Хорошо: "Кто эти люди? О чём они думают перед сном?"

### 1.4. ОБРАБОТКА ОТВЕТОВ
1. Анализ ответов
2. Если мало данных → уточняющий Drill Down
3. Если достаточно → "ДАННЫЕ ПРИНЯТЫ. Формирую Research Brief."

## РАЗДЕЛ 2: HYPOTHESIS-HEAVY DETECTION

### 2.1. ПРОТОКОЛ ОПРЕДЕЛЕНИЯ
КОД ДОСТУПА: [HYPOTHESIS_HEAVY_V1]

После обработки ответов QUERY (Слой E) — оцени качество данных:

| Условие | Оценка |
|---------|--------|
| Есть действующий бизнес с данными о продажах | HIGH / LOW |
| Есть данные об аудитории (опросы, интервью, отзывы) | HIGH / LOW |
| Сегмент покупателей подтверждён данными | HIGH / LOW |
| Продукт решает проблему, за которую уже платят | HIGH / LOW |

**Маркер HYPOTHESIS-HEAVY:** Если 2+ из 4 условий = LOW → пометить в research_brief.md:
```
## Data Quality: HYPOTHESIS-HEAVY
Причина: {перечислить LOW-условия}
```

**Влияние маркера:**
- Субагент S усилит WebSearch (7+ запросов вместо 3-5)
- DATA_CONFIDENCE_CHECK будет строже
- Рекомендация: глубина STANDARD или DEEP (не QUICK)

**Без маркера:** 0-1 условий = LOW → дефолт = DATA-SUPPORTED.

## РАЗДЕЛ 3: ВЫБОР ГЛУБИНЫ ИССЛЕДОВАНИЯ

### 3.1. DECISION TABLE
КОД ДОСТУПА: [RESEARCH_DEPTH_V1]

| Фактор | QUICK | STANDARD | DEEP |
|--------|-------|----------|------|
| Время | 1 сессия | 2-3 сессии | 4-5 сессий |
| SIMULATION | Пропуск | 5-8 персон + 1-2 скептика | 8-12 персон + 2-3 скептика |
| Сцены | 8 минимум | 12 минимум | 15+ |
| VOC минимум | 10 цитат | 15 цитат | 25 цитат |
| Тренды | Обзорные | Детальные | Прогнозные |
| Belief Map | Базовая (3 категории) | Полная (5 категорий) | Расширенная + strength scoring |
| Objection Tree | Плоский список | 2-уровневая иерархия | 3-уровневая + веса по сегментам |

### 3.2. РЕКОМЕНДАЦИЯ ГЛУБИНЫ

| Ситуация | Рекомендация |
|----------|-------------|
| HYPOTHESIS-HEAVY + новый рынок | DEEP |
| HYPOTHESIS-HEAVY + знакомый рынок | STANDARD |
| DATA-SUPPORTED + сложный продукт | STANDARD |
| DATA-SUPPORTED + простой продукт | QUICK |
| Пользователь говорит "быстро" | QUICK |
| Первый ресерч в нише | STANDARD или DEEP |

**ПРАВИЛО:** Рекомендуй, но решает пользователь. Покажи таблицу и дай рекомендацию с объяснением.

## РАЗДЕЛ 4: RESEARCH BRIEF

### 4.1. ФОРМАТ
КОД ДОСТУПА: [RESEARCH_BRIEF_V1]

```markdown
# Research Brief: {название проекта}

## Дата: {дата}
## Глубина: {QUICK / STANDARD / DEEP}
## Data Quality: {DATA-SUPPORTED / HYPOTHESIS-HEAVY}

## 1. ПРОДУКТ
- Название: {название}
- Описание: {2-3 предложения}
- Цена: {цена}
- Формат: {онлайн-курс / SaaS / физический товар / услуга / ...}
- Уникальность: {что отличает от конкурентов — 1-2 предложения}

## 2. АУДИТОРИЯ (что знаем)
- Кто: {описание без соцдема — через поведение и ситуацию}
- Главная проблема: {1-2 предложения}
- Что уже пробовали: {если известно}
- Имеющиеся данные: {опросы / кастдевы / отзывы / ничего}

## 3. РЫНОК (что знаем)
- Известные конкуренты: {список или "неизвестно"}
- Ценовой диапазон рынка: {если известно}
- Уровень осведомленности ЦА (Awareness по Шварцу): {1-5 или "определить"}
- Уровень искушённости рынка (Sophistication): {1-5 или "определить"}

## 4. ДОПОЛНИТЕЛЬНЫЕ МАТЕРИАЛЫ
- Ссылки: {URL сайтов, соцсетей, лендингов}
- Файлы: {загруженные файлы — транскрипты, отзывы, отчёты}
- Knowledge base: {что уже есть в knowledge/ — expert, audience}

## 5. ЗАПРОС НА ИССЛЕДОВАНИЕ
- Что исследовать: {конкретные вопросы или "полный ресерч"}
- Фокус: {аудитория / рынок / конкуренты / всё}
- Формат использования: {standalone / copycraft-integration}

## 6. EVIDENCE MAP (что знаем vs не знаем)
- ФАКТЫ: {что подтверждено данными}
- ИСТОЧНИКИ: {откуда}
- ГИПОТЕЗЫ: {что предполагается}
- ЧТО ИССЛЕДОВАТЬ: {конкретные пробелы}
```

### 4.2. BYPASS MODE
Если пользователь загрузил готовую спецификацию / brief.md из Copycraft:
1. Прочитай файл
2. Автоматически заполни Research Brief из имеющихся данных
3. Выведи Summary: "Заполнено из {файл}. Пробелы: {список}"
4. Предложи глубину на основе заполненности
5. Перейди в COLLECTION

### 4.3. INTEGRATION MODE (из Copycraft brief.md)
Если пользователь передаёт brief.md из Copycraft-проекта:
1. Прочитай brief.md
2. Смаппь поля brief.md → Research Brief:
   - Описание продукта → секция 1
   - ЦА → секция 2
   - Конкуренты → секция 3
   - Ссылки / файлы → секция 4
3. Определи пробелы (секция 6)
4. Предложи глубину
